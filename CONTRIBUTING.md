# Contributing to DIGO

Thanks for helping build a useful, transparent project.

1. Open an issue before major changes.
2. Keep pull requests focused and explain user impact.
3. Include tests for code changes and document operational/security implications.
4. Never submit private keys, seed phrases, personal data or secrets.
5. Do not add claims about supply, partnerships, donations, audits or listings without verifiable evidence.

The project maintainers may reject changes that create hidden token controls, misleading marketing, unsafe wallet flows or undisclosed financial incentives.
